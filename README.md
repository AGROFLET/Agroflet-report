# Project Report Collaboration Insights

Para el desarrollo del Project Report de AgroFlet, el equipo de NexaWeb utiliza el repositorio de documentación dentro de la organización AGROFLET en GitHub. Esta sección presenta la evidencia de colaboración de **AV1, TB1 y AV2**, siguiendo el Registro de Versiones del Informe y diferenciando las contribuciones al reporte de las implementaciones de cada producto.

**Repositorio del informe:** [Agroflet-report](https://github.com/AGROFLET/Agroflet-report). **Repositorio del backend:** [Agroflet-backend-application](https://github.com/AGROFLET/Agroflet-backend-application).
Commits consignados en el registro de colaboración de TB1: 165, distribuidos entre César (22), Adriano (12), Bernie (38), Christoper (55) y Jose (38). Estas cifras corresponden al corte histórico documentado en el informe; no representan necesariamente commits exclusivos de TB1 ni incluyen las correcciones posteriores.

Autores contribuyentes:
- Alca Morán, César Alejandro (almocesar-cell).
- Centeno León, Adriano Samir (Adri11-dk).
- Rivas Méndez, Bernie Aarón (ARivas3008).
- Rivas Castillo, Christoper Steven (CODERT0PH).
- Tello Lima, José Alejandro (j4ndrow).

La actividad del Project Report se organizó en ramas temáticas por capítulos, desde feature/chapter1 hasta feature/chapter5, además de las ramas feature/chapter6 y feature/chapterAnex. La rama develop reúne los avances del informe. Los commits permiten mantener trazabilidad sobre las modificaciones realizadas en investigación, requisitos, diseño, arquitectura y documentación de implementación.
Durante TB1, el equipo documentó el Sprint 2, las evidencias de desarrollo y ejecución de la Web Application, los servicios simulados mediante Fake API, los despliegues y la actualización de la Landing Page V2. Durante AV2 se registró la preparación del Sprint 3 y el desarrollo del backend en ASP.NET Core. El detalle de las responsabilidades por módulo se basa en el historial del backend, mientras que la colaboración sobre el informe debe evidenciarse separadamente mediante sus propios commits y pull requests. La distribución final deberá contrastarse con el Participant Performance Report del equipo.

### AV2 — Actualización del informe y Sprint 3

Para AV2, el trabajo documentado de AgroFlet se centró en el **backend RESTful desarrollado en C# / ASP.NET Core**, como evolución de la aplicación web con Fake API presentada en TB1. La incorporación al informe mantiene la secuencia de Sprints y relaciona las Technical Stories TS01–TS27 del Capítulo III con los módulos del servidor, sin contabilizar nuevamente las User Stories previamente trabajadas.

Los aspectos preparados para el reporte de la tercera entrega son:

- Actualización de **5.2.3. Sprint 3**: planificación, líderes y colaboradores, Sprint Backlog 3 y evidencias de desarrollo, ejecución, documentación de servicios, despliegue y colaboración.
- Descripción de los contextos **IAM, Fleet, Shipments, Tracking e Incidents**, además de los componentes transversales Shared y Contact.
- Trazabilidad de los contratos REST mediante controladores, pruebas automatizadas y documentación OpenAPI/Scalar; las comprobaciones registradas se distinguen de las pendientes.
- Revisión de la configuración de MySQL, migraciones con Entity Framework Core y preparación del despliegue mediante Docker/Render. **La presencia de archivos de despliegue no demuestra una publicación operativa.**
- Preparación de **5.3. Validation Interviews**: guías por segmento, formatos de registro y evaluación heurística. Las entrevistas, capturas, opiniones y resultados reales se completarán únicamente tras las sesiones.
- Preparación de **5.4. Video About-the-Product**, con estructura de contenido y espacios para enlaces y evidencias de publicación.
- Ampliación del Student Outcome 5 y corrección de portada, versiones, enlaces de navegación y duplicaciones del README.

**Alcance documental:** este README resume el material preparado para AV2. Los apartados 5.2.3, 5.3 y 5.4 deben incorporarse al archivo `05-Software-Development.md` para que sus enlaces en la tabla de contenidos funcionen en el repositorio. El trabajo del backend no acredita por sí solo una integración extremo a extremo con el frontend ni entrevistas ya ejecutadas.
